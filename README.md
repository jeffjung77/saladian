# BPMS 쉬운장부

소상공인을 위한 원화 수입·지출 전표와 기간별 집계 프로그램입니다.

## 1-3 개발본 (2026-10-24)

이 절은 아래의 이전 버전 설명보다 우선합니다.

- 회원가입은 아이디·비밀번호·확인만 입력합니다. 회원정보 변경에서는 아이디 조회와 비밀번호 변경을 제공하며, 사용등록에서 업체명·사업자번호·주소·사업자 전화·이메일·담당자·담당자 전화를 필수로 받습니다. 사용등록 자료는 Subscription에 저장합니다.
- 개발환경의 비로그인 첫 화면은 사업현황 미리보기이며, 프로그램 사용 시 로그인을 요청합니다. 로그인 후 첫 화면은 전표입력입니다. 전표집계는 보고서 하위 메뉴로 분리했습니다.
- 시스템관리자 메뉴에 회원현황, 구독관리, 업체관리, 로그조회를 제공합니다. 업체관리는 회원 소유 장부 단위의 조회 전용 화면이며 일반 장부 화면의 사용자별 자료 분리는 유지합니다.
- 작업 로그는 기능 도입 이후의 작업부터 기록하며 비밀번호·요청 본문·첨부 내용은 저장하지 않습니다.
- 보고서 5종은 조회 조건을 반영한 Excel(.xlsx) 다운로드를 제공합니다. 관리자·시스템관리자가 사용할 수 있으며 사용자 등급은 인쇄 버튼과 서버의 Excel 다운로드 요청을 차단합니다. 현재 허용 여부는 사용자 등급 기준으로, 사용등록 완료만으로 등급을 자동 변경하지 않습니다.
- 지원 브라우저에서는 저장 위치 선택창을 사용하며 그 외에는 기본 다운로드를 사용합니다. 웹 입력란의 언어 설정은 한글, 회원아이디는 영문이며 OS 한/영키 상태의 강제 전환은 지원하지 않습니다.
- 배포 시 `pip install -r requirements.txt`, `python manage.py migrate`, `python manage.py collectstatic --noinput`을 실행하고 서비스를 재시작합니다. 새 의존성은 openpyxl이며 마이그레이션 0020~0023이 포함됩니다. 운영 데이터베이스와 개인 파일은 저장소에 포함하지 않습니다.
- 검증: `python manage.py test ledger --noinput` 126개 통과, 추가 마이그레이션 변경 없음.

## 로그인과 사용자 등록

- 회원가입의 아이디 입력란 옆 `중복확인` 버튼으로 사용 가능 여부를 조회합니다. 형식과 길이를 검사하고 대소문자만 다른 기존 아이디도 중복으로 처리합니다. 아이디를 변경하면 확인 결과가 초기화되며, 가입 저장 시에도 서버가 중복 여부를 다시 검증합니다. 사전 중복확인은 아이디 예약 기능이 아닙니다.

- 접속 순서: `/` → 비로그인 시 `/accounts/login/` → 로그인 후 본인의 장부. 로그인 화면의 `신규 사용자 등록`에서 `/accounts/signup/`으로 이동합니다.
- 가입 항목은 아이디, 이메일, 업체명, 사업자등록번호, 담당자, 담당자 연락처, 비밀번호, 비밀번호 확인이며 모두 필수입니다. 업체 정보는 사용자와 1:1로 연결된 BusinessProfile에 저장됩니다. 비밀번호는 Django 기본 검증과 해시 저장을 사용하며 가입 후 로그인 화면으로 이동합니다. 이메일 인증·비밀번호 찾기는 아직 포함하지 않습니다.
- 사업자등록번호는 숫자 10자리 또는 123-45-67890 형식을 허용하고 하이픈 형식으로 저장합니다. 실제 사업자 등록 여부를 조회하는 기능은 아닙니다. 담당자 연락처는 숫자 8~15자리와 +, 공백, 하이픈, 괄호를 허용합니다. 기존 계정과 전표는 유지하며 기존 회원의 업체 정보를 임의로 채우지 않습니다.
- 상단의 로그아웃은 POST/CSRF 보호를 사용합니다. 익명 사용자는 전표·원장·재무제표를 직접 URL로 요청해도 로그인 화면으로 이동합니다.
- 모든 전표는 소유 사용자에게만 보이며 수정·삭제도 해당 사용자만 가능합니다. 계정과목 마스터는 공통으로 사용합니다. 슈퍼유저도 일반 장부 화면에서는 자기 장부만 조회합니다.
- 기존 소유자 없는 전표는 그대로 보존하지만 신규 가입자에게 자동 배정하지 않습니다. 다음 절차로 명시한 기존 사용자에게 연결합니다. Nginx의 `bpmsuser` 비밀번호와 Django 사용자 계정은 별개이며 자동 이전되지 않습니다.

### PC에서 확인

1. 개발 서버를 실행하고 http://127.0.0.1:8000/ 에 접속합니다.
2. `신규 사용자 등록`에서 첫 계정을 만듭니다.
3. 등록한 계정으로 로그인해 매출·비용·기타전표를 입력하고 원장·재무제표를 확인합니다.
4. 로그아웃 후 다른 계정으로 가입·로그인해 앞 계정의 전표와 거래처가 보이지 않는지 확인합니다.
5. 기존 전표를 사용할 계정을 정한 뒤, 아래 명령의 `내아이디`를 실제 가입한 아이디로 바꿉니다.

```bat
cd /d C:\venvs\webapp
C:\venvs\mysite\Scripts\python.exe manage.py assign_legacy_vouchers --username 내아이디
C:\venvs\mysite\Scripts\python.exe manage.py assign_legacy_vouchers --username 내아이디 --apply
```

첫 명령은 미리보기이며 두 번째 명령만 소유자가 없는 전표를 배정합니다. 이미 다른 사용자에게 연결된 전표는 바꾸지 않습니다. 운영 서버에서도 같은 명령을 사용하되 반드시 운영 DB를 백업하고 대상 계정을 확인하세요.

### 향후 Lightsail 반영 시

1. 운영 DB 백업 후 새 코드에 대해 운영 환경변수를 적용해 `migrate`와 `collectstatic --noinput`을 실행합니다. PC의 DB로 운영 DB를 덮어쓰지 않습니다.
2. 기존 Nginx Basic 인증은 유지한 채 서비스를 재시작하고 Django 사용자 계정을 등록합니다. 필요한 경우 `createsuperuser`로 최초 관리자 계정을 생성할 수도 있습니다.
3. `assign_legacy_vouchers --username 실제아이디`로 미리보기 후 `--apply`로 운영 전표 소유자를 지정합니다. 기존 Nginx 계정과 같은 아이디를 쓰더라도 Django 계정을 별도로 만들어야 합니다.
4. HTTPS에서 Django 로그인·로그아웃·회원가입 및 사용자 간 데이터 분리를 확인합니다.
5. 앱 로그인이 정상임을 확인한 뒤 `/etc/nginx/sites-available/bpms`에서 `auth_basic`과 `auth_basic_user_file` 두 지시문을 제거합니다. 다른 설정에서 Basic 인증을 상속하는 경우 해당 서버 블록에 `auth_basic off;`가 필요합니다. SSL·프록시 설정은 유지합니다.
6. `sudo nginx -t` 성공 후 `sudo systemctl reload nginx`를 실행합니다. 익명 방문자에게 브라우저 기본 인증 팝업 대신 로그인·회원가입 화면이 열리는지 확인합니다.

현재 개발 소스는 GitHub `1-2` 브랜치에 반영합니다. Lightsail 운영 배포는 별도 요청 시 진행합니다.

## 실행 (Windows cmd)

```bat
cd /d C:\venvs\webapp
C:\venvs\mysite\Scripts\python.exe manage.py migrate
C:\venvs\mysite\Scripts\python.exe manage.py runserver
```

브라우저에서 http://127.0.0.1:8000 접속.

## 기능

- 전표 입력 화면은 매출입력·비용입력·기타전표로 나뉩니다. 매출입력은 매출액 계정(5001)과 수입으로, 비용입력은 매출원가·판매비와관리비·영업외비용·법인세비용 계정과 지출로 제한됩니다.
- 기타전표는 차변 5행·대변 5행을 나란히 입력합니다. 각 칸에서 전체 계정과목 마스터와 원화 정수 금액을 선택합니다. 사용하지 않는 칸은 비워두며, 차변과 대변 각각 한 건 이상 및 양쪽 합계 일치를 필수로 검증합니다. 행별 금액은 서로 달라도 됩니다.
- 각 행의 차변·대변은 하나의 공통 라인 적요(선택, 최대 1,000자)를 사용합니다. 전표 전체 적요는 별도로 유지됩니다. 수정 화면, 분개 상세, 거래처 원장에서도 행별 공통 적요를 확인합니다. 적요만 입력한 빈 행은 저장할 수 없습니다. 기존에 차변·대변 적요가 다른 행은 `[차변] ... / [대변] ...`로 합쳐 보존합니다.
- 날짜·거래처·적요는 전표 전체에 공통입니다. 화면에서 합계와 차액을 실시간 표시하고 서버에서도 다시 검증합니다. 전표와 분개는 함께 저장되며 수정 실패 시 기존 전표를 보존합니다. 합계 한도는 99,999,999,999,999원입니다.
- 신규 전표는 입력유형이 저장되고 수정 시 같은 유형의 화면이 열립니다. 기존 단식전표는 변환 없이 보존하며 기존 방식으로 수정합니다.
- 기타전표의 차변·대변은 수입·지출에 중복 합산하지 않습니다. 메인 화면 하단의 차변/대변 계정별 집계와 거래처별 원장의 기타전표 내역에서 조회합니다. 전표 목록의 차변/대변 내역을 펼치면 분개를 확인할 수 있습니다.

- 제공된 계정과목표를 마스터로 자동 등록하며 전표 신규 입력·수정은 마스터 선택만 허용합니다. `/accounts/`에서 코드를 포함한 전체 표를 조회할 수 있습니다.
- 표에 없는 기존 자유입력 계정과목은 보존하고 `기존 과목 · 재선택 필요`로 표시합니다. 기존 전표 수정 시 등록 과목을 선택해야 저장됩니다. 명칭이 정확히 일치하는 단일 계정만 자동 연결합니다.

- 전표 입력·수정·삭제 (삭제 전 확인)
- 일자, 수입/지출, 계정과목, 거래처, 원화 정수 금액, 적요
- 시작일/종료일로 조회 (양 끝 날짜 포함)
- 수입 합계, 지출 합계, 차액, 계정과목별 합계
- SQLite 영구 저장: db.sqlite3
- 거래처별 원장: `/partners/ledger/`에서 거래처와 기간을 선택해 날짜순 거래 내역, 수입·지출 합계, 기초·기말 누계를 조회합니다. 거래처 미입력 전표도 선택할 수 있습니다.
- 거래처 누계는 수입에서 지출을 뺀 금액이며 외상 미수금·미지급금 잔액은 아닙니다. 거래처는 등록된 마스터의 식별자로 구분합니다.

## 거래처 마스터

- 관리자·시스템관리자는 `관리 → 거래처관리 → 거래처 등록`에서 거래처명·사업자등록번호·대표자·주소(필수), 담당자·연락처·이메일·은행명·계좌번호·비고(선택)를 저장합니다. 거래처구분과 자동번호, 사업자등록증 PDF(선택, 최대 10MB)를 지원합니다.
- 거래처는 사용자별로 분리하며 같은 사용자 안에서는 동일한 거래처명을 중복 등록할 수 없습니다. 다른 사용자의 거래처는 목록·전표 선택·원장에 나타나지 않습니다.
- 매출·비용·기타전표는 등록된 거래처를 선택합니다. 거래처 미지정도 가능합니다. 입력 중 `거래처 등록 (새 창)`에서 거래처를 저장하고 `목록 새로고침`을 누르면 전표 입력 내용을 유지한 채 새 거래처를 선택할 수 있습니다.
- 기존 사용자 소유 전표의 거래처명은 사용자별·동일 이름별로 자동 등록하고 연결합니다. 소유자가 없는 전표는 보존하고, 나중에 `assign_legacy_vouchers` 명령으로 배정할 때 해당 사용자의 마스터에 연결합니다.
- 마스터의 내부 식별자로 연결하므로 거래처명 변경 후에도 기존 전표와 원장을 함께 조회합니다. 기존 전표의 원래 입력 문자열은 보존하되 화면에서는 연결된 마스터의 현재 이름을 표시합니다. 사용 중인 거래처는 DB 참조로 보호합니다.

## 재무제표 조회

- 계정별원장: `/accounts/ledger/`에서 계정과목과 기간을 선택합니다. 시작일 이전 기초잔액, 기간 차변·대변 합계, 날짜순 거래 내역, 거래별 잔액과 기말잔액을 조회하고 인쇄할 수 있습니다. 잔액은 차변−대변 기준으로 계산하고 차변/대변 방향과 절댓값으로 표시합니다. 손익대체 전표를 포함하며, 분개와 단식전표의 반영 검증은 재무제표와 동일합니다. 복합전표는 라인 적요를 우선 표시하고, 정보가 부족한 전표는 시작일 이전분까지 미반영 안내합니다.

- 대차대조표(재무상태표): `/reports/balance-sheet/`에서 기준일을 선택합니다. 기준일까지 입력된 반영 가능 전표를 모두 누적해 자산·부채·자본을 표시합니다. 차감계정은 음수로 표시하며, 수익·비용의 미결산 잔액은 자본의 미결산 누적손익으로 반영합니다. 대차 차액도 확인할 수 있습니다.
- 손익계산서: `/reports/income-statement/`에서 시작일·종료일(양 끝 포함)을 선택합니다. 매출액, 매출원가, 판매비와관리비, 영업외수익·비용, 법인세비용과 매출총이익·영업이익·세전이익·당기순이익을 표시합니다. 기본 기간은 올해 1월 1일부터 오늘까지입니다.
- 매출·비용 전표는 상대계정을 필수로 선택합니다. 수입은 상대계정 차변/계정과목 대변, 지출은 계정과목 차변/상대계정 대변으로 계산합니다. 기타전표는 저장된 분개를 그대로 사용합니다. 원금 차입·상환과 자산 취득은 손익계산서에서 비용·수익으로 처리하지 않습니다.
- 기존 전표의 계정과목·상대계정은 추측하지 않습니다. 빠진 정보가 있는 전표는 보고서에 미반영 사유와 수정 링크를 표시하며, 이때 보고서는 잠정 집계입니다. 기존 단식전표를 수정해 실제 상대계정을 선택하면 보고서에 반영됩니다.
- 기초 잔액은 실제 자산·부채·자본에 맞게 기타전표로 입력해야 합니다. 감가상각, 재고 조정, 세금 등은 자동 계산하지 않으며 필요한 분개를 입력해야 합니다. 계정과목표의 원문 분류를 따릅니다.
- 기타전표에서 `손익대체 결산전표`를 선택하면 손익계산서에서만 제외합니다. 이 표시는 수익·비용을 이익잉여금으로 대체하는 전표에만 사용하며, 일반 결산 조정(감가상각 등)에는 선택하지 않습니다. 대차대조표는 대체 전표까지 포함한 잔액을 사용하므로 대체한 손익을 자본에 다시 합산하지 않습니다.
- 두 보고서에서 인쇄를 지원합니다. 입력 장부를 바탕으로 한 관리용 보고서이며 법정 재무제표 자동 작성·신고 기능은 아닙니다. 기준일 재무상태와 기간 손익을 구분하는 구성은 [IFRS Foundation IAS 1 소개](https://www.ifrs.org/issued-standards/list-of-standards/ias-1-presentation-of-financial-statements.html/)를 참고했습니다. IFRS 준수를 표방하지 않습니다.

로그인한 사용자별로 장부를 분리하는 MVP입니다. 기타전표의 차변·대변 입력과 장부 기준 재무제표 조회를 지원하며, 자동 결산·세무 신고·사업장 공동관리 기능은 포함하지 않습니다. 운영에서는 HTTPS와 운영 보안 설정을 유지해야 합니다.

## 1-2 개발버전

- 로그인 후 `/`에서 사업현황 한눈에 보기: 현금·예금 잔액 추이, 이번 달 손익, 요약대차대조표를 조회합니다. 기존 전표·집계는 `/vouchers/`입니다.
- 사용자 등급: 사용자 / 관리자 / 시스템관리자. 관리 메뉴는 관리자 이상, 시스템관리는 시스템관리자만 접근합니다. 시스템관리에서 신규 회원 등록·회원현황·등급 변경을 지원합니다. 공개 회원가입은 사용자 등급으로만 등록됩니다.
- 최초 시스템관리자는 `python manage.py createsuperuser`로 만듭니다. 로컬의 sysadmin 계정과 회원 DB는 Git에 포함하지 않으므로 새 환경에서 별도로 생성해야 합니다.
- 기본 계정과목은 공통 마스터이며, 신규 계정과목과 사용·비사용 설정은 장부 사용자별입니다. 비사용 계정의 기존 전표·보고서 조회는 유지됩니다.
- 기타전표는 차변·대변 계정코드 입력, 계정명 검색, 기존 선택 목록을 함께 제공합니다. 금액 입력에는 천 단위 콤마를 지원합니다.
- 부가세는 자체 분류 T/E/Z/X, 매출·매입, 증빙, 공제 구분과 별도 세액을 저장합니다. 매출·비용은 공급가액에 부가세를 더해 상대계정에 반영하고, 기타전표는 세액 분개를 직접 입력·검증합니다. 홈택스 전자신고 코드는 아닙니다.
- PDF는 `private_uploads/`에 저장하고 소유자 검증 다운로드 경로로만 제공합니다. 운영 Nginx에서 이 디렉터리를 공개하지 않으며, 운영 백업에는 DB와 함께 첨부 디렉터리를 포함합니다.
- 새 코드를 적용할 때 `python manage.py migrate`와 `python manage.py collectstatic --noinput`을 실행합니다. `config/settings.py`는 로컬 개발용이므로 운영에서는 별도 운영 설정을 적용합니다.
